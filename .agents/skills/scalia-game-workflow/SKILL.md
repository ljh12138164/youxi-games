# 游隙游戏工作流

先读根目录 `AGENTS.md`，按用户本次要求判断研究、文档、游戏开发、验收还是 CI/CD。保留当前阶段和已有授权，不把 roadmap 全文当作开发或上线授权。

## 按任务读取资料

- 游戏规则研究或开发：读对应 `games/<slug>/` 文档、代码及已有报告。区分已核实规则、项目设计与未知项；不把文档数量或测试数量当作规则完整度。
- 平台接入与游戏验收：读 [README 的接入与验证约定](../../../README.md)，使用仓库 `scripts/platform-selftest.mjs` 和对应游戏 `tests/platform-driver.mjs`。本脚本依据平台协议编写，并非官方发布的工具。
- CI、授权、首次上架、自动更新或发布故障：读 [CI/CD 说明](../../../docs/CI-CD.md)、`.github/workflows/ci.yml`、`deploy/games.json`，必要时读 `scripts/deploy-games.mjs`、`scripts/scalia-release.mjs` 与 `scripts/scalia-cloud-state.mjs`。这些文件是当前实现依据。

## 开发与检查

每款游戏独立放在 `games/<slug>/`，不跨游戏导入业务逻辑，存档保持独立命名空间。新增入口使用已有 `new:game`，发布包使用 `build:game`。只修改本次任务需要的内容，不提前创建玩法或通用引擎。

新增玩法测试放在 `games/<slug>/tests/*.test.ts`；`pnpm test` 会自动发现。发布流程测试在 `scripts/tests/*.test.mjs`。新增游戏需提供能观察实际运行/暂停状态的平台驱动，不能只凭消息回执宣布合规。

按变更运行适用检查。游戏开发完成时使用已有验收方案核对真实玩法、暂停、音频、存档及适用设备；保留未执行和阻塞项。已有检查通过且没有相关新变更时，复用结果，不反复全量手测。

## 首发与更新

`deploy/games.json` 是允许自动上线的清单：

- `gameId` 绑定经核对的已上架游戏，只替换文件。
- `create` 显式允许创建新游戏并首次发布，填写真实元数据；不能与 gameId 同时出现。首次创建后，云端持久绑定 UUID，后续直接更新。
- 首发示例与字段定义只维护在 CI/CD 说明中。不要把规划、模板或测试用游戏加入真实发布清单。

main 推送或 main 手动工作流会自动发布清单游戏，PR 不发布。已获授权的自动发布流程无需每次重复确认；仅研究、文档或本地开发不自动扩大为新增上线授权。

先上传并验证同一次成功 CI 的指定产物，再冻结和发布准确候选。自动门禁要求包摘要匹配，平台自动自测 passed、0 failed、0 blocked。不要另传本机旧包或根据“最近一次构建”猜产物。

保护已有游戏：核对 UUID 与 slug；冲突停止，不能按标题或 slug 接管对象。不得删除重建、自动恢复下架游戏、修改站点配置或其他游戏资料。多游戏按清单串行发布，失败停止后续，不能声称整批事务回滚。

## 状态、授权与故障

构建和发布都在 GitHub 托管 runner 执行，不能引入依赖用户电脑开机的 self-hosted runner。`SCALIA_STATE_KEY` Actions Secret 解密独立 `scalia-ci-state` 分支的 `release-state.enc.json`；文件使用 AES-256-GCM，同时保存授权和创建意图/UUID。明文 token 不进入 Git、日志、游戏包或回执。回执仅包含无 token 的绑定备份。

通过本次任务的 GITHUB_TOKEN（contents:write）原子更新状态文件，不能写 main；不额外保存个人 GitHub token。刷新令牌后立即保存密文，创建前等待意图云端保存成功，取得 UUID 后立即保存。状态写入冲突必须停止。不要用会淘汰的 cache 或有限保留期 artifact 代替持久绑定。平台连接最长 30 天仍需浏览器重新授权，不能声称永久有效。

创建响应丢失重放原幂等请求；已取得 UUID 则复用。状态丢失先恢复回执，已有 slug 不能自动接管。发现修订冲突、未发布资料变化或元数据与创建意图不符时停止写入并核对。

CI/CD 排障专注失败步骤、runner、变量、授权、状态和发布回执。用户要求打通自动更新、且游戏正常运行时，不转为反复游戏验收。能明确失败原因就修复它；没有新信息时不循环重试或反复检查页面。

交付说明实际提交、CI 运行与各游戏 published/unchanged/failed 状态。区分模拟首发测试与真实平台发布；不为测试自动创建无意义的线上游戏。
