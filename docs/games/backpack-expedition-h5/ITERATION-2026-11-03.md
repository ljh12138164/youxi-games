# 背包远征：挑战与商店迭代准备

日期：2026-11-03（北京时间）

状态：用户已授权基于方案实现，商店、三件装备、独立物品图像及挑战精英／Boss 机制已在本地落地。实际验证见 [实现记录](./IMPLEMENTATION.md) 与 [流程对照](./BALANCE-2026-11-03.md)。下文“已核实的现状”保留迭代前的代码基线

## 反馈与目标

用户提供的聊天截图包含两条试玩反馈：“挑战也太简单了，得加点难度，然后商店东西有点无聊”“打穿，下一个”。这是单名玩家的反馈，不能据此判断整体通关率；截图没有提供种子、存档、最终构筑或战斗过程。

本轮目标：挑战档需要根据敌人预告调整行动，商店需要提供值得重新整理背包的装备选择。保留三层、每层八站和既有森林风格，先完成一轮小范围平衡迭代。

用户补充约束（2026-11-03）：不能因增加难度导致无法正常通关。正常获取的近战、弓箭与防御反击构筑都必须保留可行通关路径，不依赖唯一掉落、顶级装备或极限操作；防御与持续伤害构筑允许花更多回合完成战斗。代表性弱构筑也需检查是否仍有补救和成长机会，但不要求任意操作、任意掉落都必胜。此约束优先于下文候选增伤数值。

## 首轮范围

### 1. 先留下挑战档对照记录

- 使用当前版本正常新局，分别走近战相邻、弓箭同行、盾牌反击路线；记录种子、路线、每场回合数、失血、补给消耗、进出店金币及最终布局
- 补充“只拿更高数值、不主动配合布局”的弱构筑对照；机器人只通过公开动作推进，不注入金币、生命或装备
- 固定种子 1–12 仅用于可复现的前后对照；记录取不到核心装备、放弃构筑和失败样本，不把缺失样本从结果中删除
- 单独检查多把零费短刀、被动护甲叠加、相邻护符叠加及第二层提前获得顶级装备，确定是否存在压倒其他选项的路径

产出：一份按构筑和种子列出的基线记录。先确定压低难度的主要来源，再冻结候选数值。

### 2. 商店先有独立价值

首轮保留四个商品位，改为一件武器、一件构筑配件、一件补给、一件自由商品；同次商品不重复。补给位保证至少一件价格不高于 16 金币的可用补给，使初始金币未花费的挑战玩家能购买。免费战利品继续现有保底规则。

增加三件商店专属候选装备，每类现有构筑各一件；通过摆位或行动代价产生取舍，先不扩展成大物品池。

| 候选 | 首轮规则草案 | 需要做出的取舍 |
| --- | --- | --- |
| 岔枝重刃 | L 形三格，2 能量、基础 13 伤害；边相邻至少一件盾牌时伤害 +5，每次使用只加一次 | 高输出占用两点能量，需在重刃、盾牌及其他武器之间分配行动 |
| 苔线长弓 | 横向三格、可旋转，1 能量、基础 7 伤害；保留同行加成，同行至少两件独立箭束时额外附加 2 层中毒，每次使用只触发一次 | 需要为多件箭束腾出同行空间；钥匙不计入两件箭束条件 |
| 回芽盾 | 二乘二四格，1 能量、基础 8 护盾；边相邻至少一件护甲时额外获得 4 护盾，每次使用只加一次；沿用现有持盾反击结算 | 盾与护甲占用相邻格，需与武器、护符争夺布局位置 |

三件装备首轮候选价均为 24 金币，稀有度 2，第二层起可出现在对应商品位；武器进入武器位，回芽盾进入构筑配件位。商品位按类型抽取候选、按 ID 排除本店已选商品，配件位可从护符、护甲及专属盾中选取。每件专属装备可以跨商店再次出现，但不是每家必出。效果与原规则不冲突，数值、价格和稀有度在对照试玩后调整。

增加每次进店限用一次的付费刷新，候选价 4 金币：替换当前未售出的全部商品，不补回已购买的商品位；本店已经售出的 ID 不再出现。刷新不能保证看到新 ID，但消耗和结果提交后固定，重载不能恢复刷新次数或重抽。已购买并放在地上的物品保持原状，确认操作时展示价格与替换范围。

商店卡片显示完整触发条件、占格、能量和价格；物品详情显示实际生效的加成来源。购买后沿用落地、换位、出售和遗留物品确认，手机沿用点击选择及放置。

### 3. 挑战精英与 Boss：保留正常通关

本轮保留三层八站、普通遭遇、敌人生命和既有难度倍率，只改变新远征挑战档精英及 Boss 的行动。轻松、标准与无版本旧档继续原行动。

| 层数 | 精英 | Boss |
| --- | --- | --- |
| 第一层 | 举盾 → 攻击 → 休整循环；破盾使下一次攻击伤害 -4 | 举盾 → 攻击 → 休整 → 攻击循环；同样可破盾减伤 |
| 第二层 | 施毒 → 攻击 → 休整循环 | 施毒 → 攻击 → 休整 → 攻击 → 举盾循环 |
| 第三层 | 蓄力 → 重击 → 休整循环；重击在原攻击上增加 6 | 第一阶段蓄力 → 重击 → 休整 → 举盾 → 普通攻击 → 休整；半血后下一回合进入第二阶段，蓄力 → 重击 → 休整 → 施毒 → 普通攻击 → 休整 |

施毒最多使玩家达到 3 层中毒。老树蓄力后的重击增加 10 点伤害，第二阶段每次攻击再增加 2 点，均为固定数值。半血转阶段不改变已显示的当前行动。预告显示实际攻击伤害，蓄力时显示下一次重击伤害；准备与战斗界面持续展示机制。

未采用原候选的第三／第五回合递增伤害。当前机制为固定的预告、应对及休整，允许防御反击和持续伤害构筑打更多回合。新规则精英掉落四件物品，至少包含本层可出的升级稀有度，保留原有武器／补给保底；金币仍为 17，不把必需物品锁进精英掉落。

正常通关是硬门槛：若新增压力迫使正常防御／持续伤害构筑改走爆发路线，或只有少数理想掉落能过关，则该候选不通过。优先延后触发、降低增伤，必要时移除回合压力；完成对照实玩前，不以单次通关或自动化通过宣称平衡达标。

## 存档与实现边界

- 新规则仅用于更新后开启的新远征。拟新增可选 `ruleset: 2`；缺字段旧档继续原商品生成、原战斗规则和原物品 ID，原难度及六站／八站行为保持有效
- 行动序列由回合及敌人类型推导，破盾与转阶段进度随存档保留，不新增通用状态系统。刷新次数和剩余商品随存档保存，读档不重新生成
- 新增物品使用新 ID；不删除或修改旧 ID 的基础规则。存档校验拒绝未知规则版本及非法刷新次数
- 旧档兼容需要在规则入口保留原规则分支，并用旧档回归证明兼容，不能只给新字段加默认值
- 修改范围限本游戏代码、测试、必要素材和对应文档；先复用既有图集作为开发占位，三件装备的正式辨识度在验收前补齐
- 本轮开发不修改发布清单，不覆盖用户已有存档，不新增依赖

## 开发顺序与验收

| 顺序 | 交付 | 通过条件 |
| --- | --- | --- |
| 1 | 挑战基线与候选数值记录 | 三类构筑及弱构筑有正常获取路径记录；缺失与失败如实列出 |
| 2 | 规则版本、商店分池、三件装备、单次刷新 | 按真实占格与行动规则验证效果；买卖和刷新无重复扣款；已售位不补回；重载结果一致 |
| 3 | 挑战精英／Boss 机制 | 破盾减伤消耗、蓄力／休整、施毒上限、半血下一回合转阶段、读档及预告与实际伤害一致；轻松与标准不启用 |
| 4 | 对照试玩与回归 | 新旧存档正常续玩；三类构筑均有正常获取后完成三层的实玩记录，且不需要某件唯一装备；强弱构筑结果分开报告 |

玩法单测放在 `games/backpack-expedition-h5/tests/*.test.ts`，浏览器回归沿用现有驱动。规则边界测试可以构造战斗状态；完整构筑记录必须从新局经正常掉落、购买与摆放获得，不能用构造状态代替可达性证据。

自动化对照报告记录每场伤害、回合数和资源，而非只看总通关数。真人试玩至少覆盖三类构筑各一局，并由提供反馈的玩家或同等熟练玩家再试玩挑战档，记录具体决策与感受；真人验证未完成时不宣称难度已解决，不设未经验证的胜率目标。

开发后执行 `pnpm test`、`pnpm run typecheck`、`pnpm run lint`、整站和本游戏独立构建，并检查桌面及 390px 手机的商品、预告、购买落地和刷新确认。沿用平台驱动验证暂停与存档，历史报告仅作基线，不能充当新玩法验收。

## 后续再评估

更多层数、无尽模式、每日挑战、局外成长、合成、锻造、商人职业与整批新美术不在首轮范围。先验证这三件装备、商店选择和挑战压力是否带来新的布局与行动决策，再决定扩展方向。
