以《Backpack Hero》的“整理背包参与构筑、探索、回合制战斗”为玩法参考，设计独立的单人 H5 游戏。用户已明确要求：做出自己的像素风格，先确认风格再开发。

本路线图建议保留的体验是：捡到物品 → 在有限格子里旋转与摆放 → 形成装备配合 → 根据敌人意图使用物品 → 获得战利品与扩容 → 继续远征。物品的位置必须影响战术，而不只是仓库容量。

以下都是待评审的项目设计，不表示原作规则，也不表示用户已经确认内容规模：

- 首版电脑浏览器、单角色、单局约 20–35 分钟，以完整的三层远征为目标。
- 鼠标拖放与点击为主，支持旋转快捷键和可点击旋转按钮。手机触控在后续单独规划。
- 原创角色、世界观、物品、敌人、文字、美术与音频；不提取参考游戏资源。
- 首版只做局内构筑、简单图鉴和本地续玩；多角色、城镇经营、联机、无尽模式、复杂局外数值成长不在首版。
- “背包快递”不作为本方案主题。正式题材、名称随美术方向确认，当前名称只是文档定位。

## 3. 第一关：先确认原创像素风格

初始约定为风格先确认再开发。用户于 2026-11-01 选择 B 后再次明确要求继续开发，据此以 B 和关键画面为实现基线；未完成的动画及素材变体保留在 M4，不再等待逐项确认。以下 A0–A2 记录原先的评审方案。

### A0：提出三个可比较的原创方向

先提出三个候选世界，每个方向回答：主角是谁、背包为什么重要、物品来自哪里、敌人是什么、画面如何一眼区分于参考作品。

每个方向提供同样的评审材料，避免只凭题材名选择：

1. 一张配色与材质板：环境、背包、金属、布料、发光物的表达。
2. 同一场景的战斗画面草图：角色、两名敌人、装有物品的背包、敌人意图、结束回合按钮。
3. 同尺度的角色、武器、盾、消耗品样例；展示原始像素尺寸与整数放大效果。
4. 简短说明视觉辨识点，以及与参考游戏角色轮廓、配色、界面构图的区别。

本路线图不预先选定其中一套，也不把“加像素滤镜”视为原创风格。

### A1：选定方向并完成关键画面

在用户选中的方向上，完成可确认的视觉包：

- 完整战斗画面：正常回合、物品选中、摆放是否合法、相邻加成高亮、敌人攻击预告。
- 战利品整理画面：新物品与已有物品的层级清楚，能理解放弃和确认的结果。
- 小型素材板：主角、两类敌人、至少八件不同类别物品、一组地牢地块和 UI 控件。
- 主角待机、攻击和受击的短动画样片，确认运动节奏与像素一致性。

评审要求：在实际显示尺寸下，看清物品形状与占格；伤害、护盾、能量和意图不依赖颜色单独传达；背包边缘和物品轮廓不混在一起；中文说明可读。像素画不要求中文文字也使用难读的小点阵字体。

### A2：风格确认与冻结

用户明确确认后，记录确认日期、所选样稿路径及尚需修改的内容，并在本游戏文档目录写入 `DESIGN.md`：

- 角色与场景比例、物品格子基准、统一逻辑像素尺度、轮廓及阴影规则。
- 主色板、功能色、光源方向、材质表达；受击与稀有度的表现方式。
- UI 面板、按钮、工具提示、字体、间距和状态表达。
- 动画帧数与节奏、整数缩放、宽屏及较小窗口下的布局策略。
- 资源命名、来源、许可和导出规范。

不能仅凭确认某一张角色图就视为整套界面风格通过。方向性变更需要重新提供关键画面对照；一般修边、对齐和状态补齐不重复走整套选型。

## 4. 拟定核心规则

以下规则在 M0 冻结；数值可通过试玩调整，规则变化要同步更新说明和测试。

### 4.1 背包与物品

- 背包使用有边界的格子集合，物品使用整数格坐标描述形状；首版先支持矩形与 L 形。
- 物品以 90° 旋转，禁止越界、覆盖未解锁格子或与其他物品重叠。非法拖放回到原位，不丢物品。
- 相邻定义为两件物品至少一格边相接，斜角不算；同一物品不会因接触多条边重复获得同一来源加成。
- 首版支持四种明确效果：基础伤害、防御、正交相邻加成、同行或同列加成。工具提示展示来源和计算后的结果。
- 战斗前与战后可自由整理；战斗中锁定位置，只允许使用物品。避免每次攻击前重新排列造成重复操作和无限收益。
- 升级时从相连的可扩容格子中选择，确认前预览扩容。首版不引入嵌套背包。

### 4.2 回合制战斗

- 玩家可查看敌人下一回合意图，消耗能量使用武器、盾与消耗品，主动结束回合。
- 首版能量基准建议为每回合 3 点；这是项目初始调参值，不声称与原作一致。
- 普通物品按定义可重复使用；消耗品使用后移除。能量不足、无有效目标、次数耗尽时禁用并说明原因。
- 回合顺序：玩家行动 → 结束回合效果 → 存活敌人按固定顺序执行意图 → 结算持续状态 → 若战斗未结束，恢复玩家能量并刷新意图。
- 护盾抵挡普通伤害，玩家护盾在下一玩家回合开始时清除。首版持续状态只做中毒，明确结算时点、扣血与衰减规则。
- 战斗胜负一经确定立即停止后续行动；同时死亡、反伤或消耗品触发等边界在加入相应机制前确定。
- M1 不做自动连锁触发；M3 如需加入，只实现具名效果与可终止的结算顺序，不建立通用脚本系统。

### 4.3 探索与构筑

- 使用简洁的分叉节点地图，节点包括战斗、精英、商店、休息、事件与层末 Boss。
- 节点进入后提交结果，已完成节点不能重复领奖。战利品可整理、选择和放弃；离开前提示未带走物品。
- 拟定三类初始构筑：近战相邻增伤、防御反击、远程同行配合。反击类在 M3 加入，先验证结算规则。
- 每类构筑需要核心装备、支撑物品和可行的过渡方案；掉落池提供基础攻击与生存选择，避免必须抽到唯一物品才能推进。
- 单局失败重新开始；图鉴保留发现记录，首版不通过永久攻击力升级掩盖平衡问题。

| M3 首版 Alpha | 三层远征、三类构筑、完整胜负与新手引导 | 无调试条件下从新档打通全局；每类构筑有正常获得和成型路径 |
| M4 Beta | 完整原创像素素材与音频、信息反馈、平衡、档案及图鉴 | 无正式流程占位资源；整理与战斗易读；存档恢复、物品组合边界和浏览器测试通过 |
| M5 发布候选 | 独立 HTML、平台接入、自测驱动、资料与验收报告 | 类型检查、测试、构建、实际玩法与平台候选检查通过；未验证项目如实登记 |

M2 是第一个玩法决策点：若整理只带来麻烦而没有战术差异，先调整物品形状、布局收益和敌人设计，不继续堆内容。样机和短局都不称为完整首版。

M3–M4 的内容预算建议为：约 40 件物品（其中至少 12 件参与布局配合）、9 类普通敌人、3 类精英、3 个层末 Boss、6 个事件、1 名角色和 1 套三层路线。数量是规划预算，M0 冻结准确清单；每一项都要有可达获取方式、图像、规则说明及验证状态。

不先承诺日历工期：风格确认和 M1 完成后，按实测素材产能、交互复杂度及剩余内容估算。

## 6. 技术路径

- 延续现有 React、TypeScript、Vite 和 pnpm。优先 DOM/CSS 网格与独立像素图片，回合制不预先引入新渲染引擎或拖拽库。
- 使用 Pointer Events 处理拖动，拖动视觉位置与背包逻辑位置分开；离开窗口、失焦、取消和暂停时清理拖动状态。
- 用明确的 TypeScript 状态描述地图、整理、玩家回合、敌人结算、战利品和终局；UI 只提交动作，规则模块返回结果。
- 物品与敌人先使用简单类型化数据和具名效果函数；不做可配置游戏引擎、插件系统或自定义脚本语言。
- 确认开发后使用 `pnpm run new:game -- backpack-expedition-h5 "背包远征"` 创建入口；若改名或 slug 不可用，先同步文档。
- 全部业务与素材放入 `games/<最终slug>/`，不导入其他游戏业务。仅复用适用的 `shared/platform/` 封装。
- 图片按整数比例放大并关闭平滑采样；小窗口通过重新排版保持清晰，不将整个界面任意拉伸。
- 资源由源代码导入，目标单游戏独立 HTML、无外部运行时依赖。体积预算在视觉样本导出后测定，不在规划中虚构素材体积。

## 7. 存档与平台

首版采用一份进行中远征和独立图鉴记录，按最终 slug 与 schemaVersion 命名，不预设多存档系统。

- 保存背包形状、每个物品实例的位置与状态、地图、生命、金币、战斗状态、随机状态、已生成奖励和已领取标记。
- 每个有效动作结算完成后保存；动画只呈现已提交结果，刷新不重复扣费、攻击、消费或领奖。
- 拖动尚未放下不保存半完成位置；读档恢复逻辑状态而非拖拽、工具提示或动画中间帧。
- 保存失败必须提示；损坏数据不得直接覆盖，提供重新开始和保留原数据的恢复路径。具体备份策略在 M2 按实测存档大小决定。
- 平台隐藏、侧栏、防 Boss 和手动暂停独立维护；暂停期间不接受改变局面的操作，不继续敌人结算动画或音频。
- 区分用户静音与平台临时静音，准备完成后发送 ready；使用能观察真实暂停状态的自测驱动。
- M1 就接入最小生命周期，M5 完成协议与实际玩法验收。平台身份、最近游玩等真实外壳检查单列发布后执行。

## 8. 验证重点

| 范围 | 必测场景 |
| --- | --- |
| 空间规则 | 非矩形背包、四次旋转回原形、边界与碰撞、相邻去重、扩容连通、放置失败回退 |
| 战斗 | 能量不足、护盾清除、中毒结算、敌人死亡后不行动、最后一击、无效目标、连续点击不双结算 |
| 经济与奖励 | 购买后空间不足可回退；掉落放弃；消费与领奖只提交一次；读档候选不改变 |
| 保存 | 战斗前后、敌人回合、领奖前后刷新；损坏存档；旧 schema；图鉴与远征隔离 |
| 交互与画面 | 拖动途中失焦或暂停、旋转提示、占格与加成来源、长中文说明、小窗口不遮挡操作 |
| 完整流程 | 新档引导、三类构筑、正常胜利、失败重开、关页续玩、平台遮盖和静音恢复 |

规则测试放入 `games/<slug>/tests/*.test.ts`，由现有 `pnpm test` 发现。浏览器测试必须实际操作拖放、旋转、物品使用与结束回合，不能只调用内部状态函数宣布交互通过。

本次为文档变更，按项目要求执行 `pnpm run typecheck`。后续实施按改动执行：

```powershell
pnpm run typecheck
pnpm test
pnpm run build
pnpm run build:game -- backpack-expedition-h5
```

单游戏构建命令仅在实际创建入口且最终 slug 确定后适用。平台测试按仓库已有 `scripts/platform-selftest.mjs` 的当时用法执行，并保留报告。
