# 《温室值夜》H5 完整版本开发路线图

《温室值夜》是工作名称，项目标识暂定 `greenhouse-watch-h5`。交付目标是完整实现约定基准版本的可玩内容和网页端功能。战斗、关卡、数值、解锁、操作和界面流程都按实际运行结果核对。

当前使用独立重实现的 C++ 源码编译成 Wasm，网页随包加载本地美术和音频资源。核心包含 50 关战役、小游戏、解谜、生存、图鉴、商店、花园和成就。游戏进度与可保存关卡使用浏览器 IndexedDB。修改器可调整倍速、增加阳光、设置金币、解锁附加模式和关卡，也可指定冒险关卡和额外开局阳光。

执行 `pnpm run build:greenhouse:wasm` 从固定版本的源码重新编译。Windows 使用 WSL，Linux 直接运行构建脚本。首次编译需要 Git、CMake、Ninja、Make 和 Emscripten。CI 在构建 H5 产物前编译核心。

桌面浏览器实测普通冒险放置与保存，刷新后续回原对局并核对阳光值。代表性小游戏、解谜、生存和最终战均进入实战，背景音乐已确认有输出。完整战役逐关通关与真实手机体验仍待验收。

## 1. 范围与对照方法

对照时锁定本地参考版本和核查日期，逐个走查游戏菜单、新档流程、章节和附加模式，再对同一批内容验证网页构建。按项目内部 ID 建立覆盖台账。每项记录入口、前置条件、规则与参数、验收用例和核查状态。首轮遍历后统计各模式关卡、单位、敌人及其他可解锁内容的实际数量，作为验收分母。

所有可通过正常流程、菜单、解锁、条件触发或功能入口到达的内容都纳入范围。遇到尚未解锁、需要账号或只有旧存档才能进入的功能，保留待核实状态并记录复查条件。网页启动器和游戏内功能都逐项验收。宿主网站的社区侧栏、账号页面和互动入口由目标平台承担，游戏内受这些能力影响的功能仍须验证。

## 2. 游戏内覆盖清单

| 范围 | 核对内容 |
| --- | --- |
| 战役与教学 | 逐关实现棋盘、环境、开放路线、教学指引、初始资源、预置单位、选卡规则、波次、奖励、失败与结算。覆盖全部章节、最终战、通关后的内容和重玩入口。 |
| 植物与敌人 | 逐个核对获取条件、价格、冷却、生命、速度、索敌、攻击间隔、命中范围、特殊技能、受控状态及死亡后的规则。包含敌人的装备、召唤物和首领阶段。 |
| 战斗交互 | 覆盖选卡、落位、取消、移除、养分收取、地形限制、支撑与叠放、投射物、应急防线和特殊工具。对照命中、失守、暂停与终局的结算先后。 |
| 附加模式 | 逐项核对小玩法、解谜、生存和无尽类内容中实际可达的关卡，包含通过全解锁入口可见的额外关卡。保留模式独有的布阵限制、回合变化、奖励、失败后果与续玩方式。 |
| 局外内容 | 逐项核对商店、道具、图鉴、养成、成就或统计中实际可达的条目，以及金币、消耗品、解锁和重复游玩的关系。 |
| 界面与表现 | 对照标题页、档案、选关、战前、战场和结算流程。逐场景核对布局、缩放、输入反馈、角色动画、命中、波次预警及音乐和音效的触发点。 |

前几关用于贯通从新档到结算的链路。之后按章节和模式补齐全部内容，持续用同一份台账核对进度。对掉落、波次、敌人状态等含随机性的行为记录分布或可见约束。能够控制随机种子时，记录输入序列并对照结果。

## 3. 网页端功能

| 功能 | 实现与验收 |
| --- | --- |
| 启动与输入 | 保留加载进度、失败信息、启动动作和恢复入口。桌面核对鼠标和键盘，手机核对触控、横屏及软键盘。对照等比缩放后的位置映射和画面比例选项，全屏由游隙外壳控制。 |
| 设置 | 对照音效和音乐分轨音量、自动和手动帧率设置、帧率显示、横版界面与窄窗口回退、画面比例。WebAssembly 路线按目标浏览器验证图形后端和内存模式的检测、切换与回退。 |
| 本地进度 | 保存用户档案、解锁、局内阵容、波次和继续游戏所需的状态。分别验证正常退出、刷新、关卡切换、存储异常以及部署新版本后的读取。 |
| 存档与阵型工具 | 对照自定义档案、关卡存档、可视化布阵和阵型库，复现导入、导出、覆盖确认和可验证的无尽换轮存档修复。用有权使用的样本验证二进制及文本格式，失败时保留原档。 |
| 本地备份 | 阵型库、游戏进度和局内状态均使用本地存储。需要换设备时通过存档导出与导入迁移。 |
| 特殊解锁与诊断 | 核对启动时的全解锁开关及其权限，确认开启后可访问对应关卡且用户原有进度保持一致。核对受权限控制的存档工具、失败反馈、诊断开关与导出。 |

档案、阵型和工具均以本地数据为验收范围。全解锁与存档工具在目标环境的入口和操作仍需逐项对照。

## 4. 实现、素材与构建

C++ 核心以单线程 Wasm 构建，负责战斗、标题画面、菜单、渲染和音频。打开页面后直接进入标题画面。网页层加载资源，提供修改器和语言设置，并处理本地存档与平台消息。核心版本与构建配置固定在游戏的 `core/` 目录。

开工时用 `pnpm run new:game -- greenhouse-watch-h5 "温室值夜"` 建立独立入口。代码、素材和测试集中在 `games/greenhouse-watch-h5/`。游戏样式导入 `@shared/styles/tailwind.css` 并显式扫描本游戏源码。战斗模拟使用统一时钟，配合截图、事件记录和存档样本做对照。

按画面、角色、动作、特效和音频建立素材清单，优先复用许可覆盖预定用途的素材，保留相同的帧序、锚点、播放速度与触发时机。授权未核实的条目用占位资源完成规则开发，并保留美术或音频验收缺口。可发布产物附上适用的许可和署名。

优先交付包含 `index.html`、JS、CSS、Wasm 和素材的完整静态目录或 ZIP。资源使用同包相对路径，核对平台实际响应的 MIME、CSP 和容器行为。游隙当前限制为 ZIP 100 MiB、解压 500 MiB、单文件 64 MiB、最多 10,000 个文件。构建和验收使用 GitHub 托管 runner。[游隙上传与发布](https://scalia.ltd/docs/publishing)

## 5. 里程碑与完成标准

| 阶段 | 可核验交付 |
| --- | --- |
| M0 · 对照台账与技术验证 | 确定基准构建并列出实际可达的功能。为受权限限制或暂未走查的入口记录待核实项。用最小 Wasm 包验证模块初始化和平台生命周期。 |
| M1 · 首段贯通 | 从启动器到新档、教学、战斗、结算和关内续玩跑通。以同一组操作对照画面、波次、经济、单位交互与存档。 |
| M2 · 完整内容 | 对照台账实现并逐条核验全部战役、单位、场景、附加模式、终局、奖励和局外功能。完整跑通至少一个新档的自然解锁路径，并逐项进入各附加模式验收。 |
| M3 · 网页功能与候选 | 完成设置、本地存档维护、阵型工具、诊断与特殊解锁功能。桌面和真实手机验证输入、声音、存档和性能。用同一份发布产物通过包体检查、候选加载和平台自动自测，达到 0 failed、0 blocked。 |

调用 `ready()` 前确认资源和游戏实际可用。手动暂停、游戏菜单、平台侧栏和防 Boss 分别维护暂停原因。测试驱动读取真实波次和模拟时钟，验证恢复只清除对应原因，并核对平台临时静音覆盖已有及新建音源。候选页验证静态文件，完整平台外壳验证身份、快捷键、侧栏和音频。[游隙游戏接入](https://scalia.ltd/docs/game-integration)

完整验收要求台账内每个条目都有实际通过记录，逐项核对缺失内容、数值差异、存档兼容及平台依赖。实施阶段执行 `pnpm run typecheck`、`pnpm run lint`、`pnpm test`、`pnpm run build` 和 `pnpm run build:game -- greenhouse-watch-h5`。经授权后按仓库 CI/CD 流程发布同一份通过验收的产物。[仓库发布流程](../../CI-CD.md)
